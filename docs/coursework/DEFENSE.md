Моя система BeerCinema автоматизирует все эти процессы. В системе четыре актора: гость видит афишу и расписание, клиент бронирует и оплачивает билеты и пишет отзывы, менеджер управляет фильмами и сеансами, администратор — еще и пользователями.

**[Слайд 4]** Системная архитектура: браузер по HTTPS обращается к веб-сервису на Render.com, где работает приложение на NestJS. Приложение хранит данные в PostgreSQL, работая с ней через ORM Prisma, а постеры фильмов — в объектном хранилище Yandex Object Storage по протоколу S3.

**[Слайд 5]** Архитектура данных — шесть сущностей: пользователь, фильм, зал, сеанс, билет, отзыв. Сеанс связывает фильм и зал, билет — сеанс и пользователя. Уникальный индекс по паре «сеанс + место» на уровне базы исключает двойное бронирование одного места.

**[Слайд 6]** Программная архитектура модульная: на каждую сущность — модуль NestJS с одним сервисом бизнес-логики и тремя входными точками: MVC-контроллер отдает HTML-страницы, REST-контроллер — JSON, GraphQL-резолвер — данные по запросу клиента. Логика написана один раз и переиспользуется всеми тремя интерфейсами.

**[Слайд 7]** REST API документирован автоматически через Swagger: у каждой сущности есть CRUD-операции, пагинация с заголовком Link, валидация входных данных через DTO. Для списка фильмов работают серверный кэш и условные запросы: при совпадении ETag сервер отвечает 304 без тела. GraphQL API дополнительно дает семантические мутации — забронировать, оплатить, отменить билет — и ограничение глубины запросов.

**[Слайд 8]** Авторизация сессионная: пароль хранится только как bcrypt-хеш, после входа сервер создает сессию, браузер получает httpOnly-куку. Guard'ы проверяют сессию и роль: гость при попытке открыть защищенную страницу перенаправляется на вход, клиент без нужной роли получает 403.

## Вопросы и ответы

По ЛР4 и ЛР6 уже есть разборы вопросов в docs/LAB4-DOC.md и docs/LAB6-README.md. Ниже — дополнительные по курсовой.

**Почему NestJS, а не чистый Express?**
NestJS дает готовую модульную архитектуру, внедрение зависимостей, декораторы для маршрутов, валидации и Swagger. На Express все это пришлось бы собирать вручную. Внутри NestJS все равно работает Express.

**Почему PostgreSQL?**
Реляционная модель хорошо ложится на предметную область: много связей 1:N и ограничений целостности (уникальность места на сеансе, внешние ключи). PostgreSQL — стабильная свободная СУБД, которую поддерживает хостинг Render.

**Что такое внедрение зависимостей (DI)?**
Класс не создает свои зависимости сам — их подставляет фреймворк через конструктор. Например, FilmsService получает PrismaService. Это упрощает замену реализаций и тестирование.

**Чем отличаются MVC, REST и GraphQL в проекте?**
MVC отдает готовый HTML для людей, REST — JSON с фиксированной структурой для программ, GraphQL позволяет клиенту самому выбрать нужные поля и связанные данные одним запросом. Все три используют общие сервисы.

**Как работает авторизация?**
При входе AuthService сравнивает пароль с bcrypt-хешем из базы. При успехе данные пользователя кладутся в серверную сессию, браузер получает httpOnly-куку с id сессии. PageAuthGuard на защищенных маршрутах проверяет сессию, декоратор @Roles — роль.

**Почему сессии, а не JWT?**
Для серверно-рендерируемого интерфейса сессии проще и безопаснее: куку httpOnly не прочитать из JavaScript, сессию можно мгновенно отозвать на сервере. JWT удобнее для внешних API-клиентов — указано как развитие.

**Почему пароль нельзя хранить открытым и что такое bcrypt?**
При утечке базы открытые пароли компрометируют пользователей. bcrypt — медленная хеш-функция с солью: перебор дорог, одинаковые пароли дают разные хеши.

**Почему API остается открытым?**
REST и GraphQL открыты для демонстрации и проверки (Swagger, playground) — это учебный проект. Веб-интерфейс, через который работают люди, защищен полностью. Закрытие API токенами — направление развития.

**Как исключается двойное бронирование места?**
Ограничением уникальности @@unique([sessionId, seat]) на уровне базы данных. Даже при одновременных запросах вторая вставка упадет с ошибкой P2002, которую глобальный фильтр превращает в понятный ответ 409.

**Что произойдет при удалении фильма/зала?**
Сеансы фильма удаляются каскадно (Cascade). Зал с сеансами удалить нельзя (Restrict) — база вернет ошибку внешнего ключа.

**Как Swagger узнает о структуре API?**
По декораторам: @ApiProperty в DTO и entity-классах, @ApiOperation/@ApiResponse в контроллерах. NestJS собирает из них спецификацию OpenAPI 3.0 автоматически при старте.

**Зачем ограничение глубины GraphQL-запросов?**
Без него можно построить запрос фильм -> сеансы -> фильм -> сеансы... и положить сервер. depthLimit(5) отклоняет такие запросы до выполнения.

**Что такое guard и чем он отличается от middleware?**
Middleware выполняется до маршрутизации и не знает, какой обработчик вызовется. Guard выполняется после и имеет доступ к метаданным обработчика (например, к списку ролей из @Roles), поэтому подходит для авторизации.

**Как реализована пагинация?**
Параметры ?page и ?limit, в Prisma — skip/take, в ответе метаданные (total, totalPages) и заголовок Link со ссылками next/prev по RFC 5988.

**Где хранятся постеры и почему не в базе?**
В объектном хранилище Yandex Object Storage. Файлы в реляционной базе раздувают ее и медленно отдаются; объектное хранилище дешевле, масштабируется и отдает файлы напрямую браузеру по URL.
