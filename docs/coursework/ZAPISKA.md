## Введение

Объектом разработки является система управления кинотеатром BeerCinema, реализованная на языке программирования TypeScript с использованием фреймворка NestJS для серверной части приложения. Пользовательский интерфейс формируется на сервере с помощью шаблонизатора Handlebars, клиентская логика написана на языке JavaScript без использования фреймворков.

Целью работы является разработка веб-приложения и пользовательского интерфейса, анализ требований и моделирование процессов, средств автоматизации и архитектуры информационной системы.

В ходе работы были получены следующие результаты:

- Серверная часть системы, предоставляющая три программных интерфейса: веб-интерфейс (MVC), REST API с документацией по спецификации OpenAPI 3.0 и GraphQL API.
- Пользовательский интерфейс с разграничением прав доступа по ролям (клиент, менеджер, администратор).
- База данных PostgreSQL для хранения информации о фильмах, кинозалах, сеансах, билетах, пользователях и отзывах.
- Подсистема хранения файлов (постеров фильмов) в объектном хранилище Yandex Object Storage.

## Определения, обобщения и сокращения

Информационная система (ИС) — совокупность содержащейся в базах данных информации и обеспечивающих ее обработку информационных технологий и технических средств.

Браузер — прикладная программа для запроса, отображения веб-страниц и взаимодействия пользователя с веб-приложениями.

Фреймворк — программная платформа, задающая структуру приложения и берущая на себя типовые задачи (маршрутизация, внедрение зависимостей, обработка запросов).

ORM (Object-Relational Mapping) — технология отображения таблиц реляционной базы данных на объекты языка программирования.

REST (Representational State Transfer) — архитектурный стиль построения программных интерфейсов поверх протокола HTTP, в котором операции над ресурсами выражаются стандартными методами (GET, POST, PATCH, DELETE).

GraphQL — язык запросов к API, позволяющий клиенту указать, какие именно поля данных ему требуются.

MVC (Model-View-Controller) — архитектурный шаблон, разделяющий приложение на модель данных, представление и контроллер.

DTO (Data Transfer Object) — объект передачи данных, описывающий структуру входных и выходных данных API.

Сессия — механизм сохранения состояния авторизованного пользователя между HTTP-запросами; идентификатор сессии передается в httpOnly-куке.

Роль «клиент» — зарегистрированный пользователь; может бронировать и оплачивать билеты, оставлять отзывы.

Роль «менеджер» — сотрудник кинотеатра; дополнительно управляет каталогом фильмов и расписанием сеансов.

Роль «администратор» — пользователь с полными правами; дополнительно управляет учетными записями и ролями пользователей.

## Описание предметной области

### Описание прикладного процесса

Разрабатываемое веб-приложение — система управления кинотеатром. Она автоматизирует основные процессы кинотеатра: ведение каталога фильмов, составление расписания сеансов по залам, бронирование и оплату билетов, сбор отзывов зрителей.

В работе кинотеатра можно выделить следующие типовые задачи: добавление нового фильма в прокат и снятие фильма с проката; назначение сеансов фильмов в конкретные залы с учетом времени и цены; продажа билетов на конкретные места с контролем занятости места; учет зрителей и их покупок; сбор обратной связи в виде оценок и комментариев.

В системе выделены следующие модули и используемые ими информационные объекты:

- Модуль фильмов — объекты «Фильм» (Film);
- Модуль сеансов — объекты «Сеанс» (Session) и «Кинозал» (Hall);
- Модуль билетов — объекты «Билет» (Ticket);
- Модуль пользователей — объекты «Пользователь» (User);
- Модуль отзывов — объекты «Отзыв» (Review);
- Модуль авторизации — сессии пользователей и роли.

Акторы системы: гость, клиент, менеджер, администратор. Варианты использования представлены на диаграмме (рисунок 1).

### Формирование требований

В ходе анализа прикладного процесса был получен следующий список функциональных требований.

Модуль фильмов должен иметь:
- отображение каталога фильмов с постерами;
- просмотр карточки фильма с его сеансами и отзывами;
- создание, редактирование и удаление фильма (менеджер, администратор);
- загрузку постера фильма в объектное хранилище.

Модуль сеансов должен иметь:
- отображение расписания сеансов с фильтрацией по фильму и дате;
- создание, редактирование и удаление сеанса с выбором фильма и зала (менеджер, администратор).

Модуль билетов должен иметь:
- бронирование билета на конкретное место сеанса;
- контроль уникальности места в рамках сеанса;
- смену статуса билета: забронирован, оплачен, отменен.

Модуль пользователей должен иметь:
- регистрацию и вход по email и паролю;
- просмотр и управление списком пользователей и их ролями (администратор).

Модуль отзывов должен иметь:
- просмотр отзывов о фильме;
- создание отзыва с оценкой от 1 до 5 и комментарием (авторизованный пользователь).

Нефункциональные требования.

Доступ к операциям изменения данных через веб-интерфейс требует прохождения аутентификации; права разграничены ролями CLIENT, MANAGER, ADMIN. Пароли пользователей хранятся только в виде хеша (bcrypt).

Должна быть возможность работы с приложением напрямую, через общие программные интерфейсы, описанные по спецификации OpenAPI версии не ниже 3.0; дополнительно предоставляется GraphQL API с ограничением глубины запроса.

Ответы API кэшируются: применяются заголовки ETag и Cache-Control, а также серверный кэш списка фильмов.

## Проектирование

### Используемый стек технологий

Решение о создании именно веб-приложения обусловлено необходимостью обеспечить доступ к системе с любого устройства в любое время без установки клиентского программного обеспечения.

Серверная часть реализована на языке TypeScript с использованием фреймворка NestJS. NestJS предоставляет модульную архитектуру, встроенное внедрение зависимостей и декларативное описание маршрутов, что упрощает сопровождение проекта. Пользовательский интерфейс формируется на сервере шаблонизатором Handlebars (подход MVC), клиентские сценарии написаны на JavaScript, оформление — HTML и CSS (Tailwind CSS).

В качестве СУБД используется PostgreSQL как стабильная свободная реляционная СУБД. Для работы с данными выбрана ORM-библиотека Prisma: схема данных описывается декларативно, миграции генерируются автоматически, клиент типизирован.

Документация REST API формируется автоматически средствами Swagger (OpenAPI 3.0). GraphQL API реализован на Apollo Server по подходу code-first. Постеры фильмов хранятся в объектном хранилище Yandex Object Storage, доступ к которому осуществляется по протоколу S3.

В проекте используется распределенная система управления версиями Git, хранилищем исходного кода является веб-сервис GitHub, в качестве хостинга используется облачный сервис Render.com.

### Системная архитектура

Системная архитектура приложения представлена на диаграмме развертывания (рисунок 2). Браузер пользователя взаимодействует по протоколу HTTPS с веб-сервисом на платформе Render.com, внутри которого работает приложение NestJS с тремя входными интерфейсами: MVC (HTML-страницы), REST API (JSON) и GraphQL. Приложение обращается к базе данных PostgreSQL по протоколу TCP (порт 5432) через клиент Prisma и к объектному хранилищу Yandex Object Storage по протоколу HTTPS (S3 API). Постеры фильмов браузер получает напрямую из бакета объектного хранилища.

### Архитектура данных

Схема базы данных содержит шесть сущностей (рисунок 3).

[СКРИНШОТ: docs/er-diagram.png]
Рисунок 3. Схема таблиц базы данных

User — пользователь системы: email (уникальный), имя, хеш пароля, роль (CLIENT, MANAGER, ADMIN).

Film — фильм в прокате: название, описание, жанр, длительность в минутах, год выпуска, ссылка на постер, средний рейтинг.

Hall — кинозал: уникальное название, вместимость, описание.

Session — киносеанс: связывает фильм и зал, содержит время начала и окончания и цену билета.

Ticket — билет на конкретное место сеанса: связывает сеанс и пользователя, содержит место и статус (RESERVED, PAID, CANCELLED); пара «сеанс + место» уникальна, что исключает двойное бронирование.

Review — отзыв пользователя о фильме: оценка от 1 до 5 и комментарий.

Связи: User—Ticket (1:N), User—Review (1:N), Film—Session (1:N), Film—Review (1:N), Hall—Session (1:N), Session—Ticket (1:N). Удаление фильма каскадно удаляет его сеансы; удаление зала с сеансами запрещено (Restrict).

## Разработка

### Реализация серверного API

В качестве описания программного интерфейса был выбран инструмент, поддерживающий стандарт OAS 3.0 — Swagger. Документация формируется автоматически по декораторам (@ApiProperty, @ApiOperation), указанным в контроллерах и DTO разрабатываемой информационной системы, и доступна по адресу /api/docs.

REST API предоставляет для каждой сущности операции чтения списка с пагинацией (заголовок Link по RFC 5988), чтения по идентификатору, создания (POST), частичного обновления (PATCH) и удаления (DELETE), а также вложенные маршруты вида /api/films/{id}/sessions. Входные данные проверяются глобальным ValidationPipe по DTO-классам с декораторами class-validator. Для списка фильмов реализованы серверный кэш и условные запросы: при совпадении заголовка If-None-Match с ETag сервер возвращает 304 Not Modified.

## Заключение

В ходе выполнения курсовой работы была разработана информационная система управления кинотеатром BeerCinema.

Проведен анализ предметной области, выделены прикладные процессы, акторы и информационные объекты, сформированы функциональные и нефункциональные требования. Спроектирована архитектура системы: системная архитектура (клиент — сервер на Render.com — PostgreSQL — объектное хранилище), архитектура данных из шести связанных сущностей и модульная программная архитектура на базе NestJS.

Реализованы серверная часть с тремя программными интерфейсами (MVC, REST со Swagger-документацией, GraphQL), авторизация с сессиями и разграничением прав по ролям, кэширование ответов и хранение файлов в объектном хранилище. Пользовательский интерфейс покрывает все сформированные функциональные требования.

Направления дальнейшего развития системы: валидация пересечений сеансов в зале и контроль вместимости зала при продаже билетов, автоматический пересчет рейтинга фильма по отзывам, токенная авторизация (JWT) для программных интерфейсов.

# Черновик «Аннотация»

В курсовой работе рассмотрена разработка веб-приложения «Система управления кинотеатром BeerCinema». Проведен анализ предметной области и смоделированы прикладные процессы кинотеатра, сформированы функциональные и нефункциональные требования. Спроектирована архитектура информационной системы: системная (клиент, сервер приложения, база данных, объектное хранилище), архитектура данных (шесть сущностей PostgreSQL) и модульная программная архитектура на фреймворке NestJS. Реализованы серверная часть с интерфейсами MVC, REST (OpenAPI 3.0) и GraphQL, сессионная авторизация с разграничением прав по ролям, кэширование и хранение файлов в Yandex Object Storage, а также серверно-рендерируемый пользовательский интерфейс. Работа выполнена на языке TypeScript, приложение развернуто на облачном сервисе Render.com.
